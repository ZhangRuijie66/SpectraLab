## 📌 顺带修正一条版本号规则

v5.0.0 引入的「PATCH 编码修复类别」方案有缺陷，**本版起废弃**：
同一类修复做第二次时会撞号（两次都该叫 `.2`），若改成两位（`.21`/`.22`）
又要求使用者背编码表、超过 9 次仍有歧义。三段式的位置只够装「序号」，
装不下「类别 + 序号」两维信息。

改为标准做法：
- **PATCH = 同一 MAJOR.MINOR 下的第几次修复**，从 1 严格递增，不跳号、不重复；
- **类别改用文字写在 CHANGELOG 首行的「类型」里**（本版：产物/导出 + 界面）。

所以本版是 `5.0.1` 而不是 `5.0.2`——之前想按「产物=类别 2」编成 5.0.2，
但那会让将来的同类修复无处可去。

## 🔧 3D 扫描三种视图：切换后图形叠加 / colorbar 读不出刻度

### `clear_fig()` 清了跟没清一样（根因）

- **现象**：3D 扫描模式连续切换「3D 曲面 → 等高线 → 3D 曲面」时，
  画布上会**叠着上一张图**——用户看到的是"切换视图后图没变"或"两张图糊在一起"。
- **根因**：`MplCanvas.clear_fig()` 的旧实现是「`while fig.axes: delaxes(...)` 再 `clf()`」。
  `delaxes` 逐个子图删除时，**colorbar 那个独立 Axes 不受 subplot 管理、不会被一起删**；
  紧接着的 `clf()` 又把 axes 列表状态清掉，于是那些 colorbar 轴成了"孤儿"留在 figure 里。
  实测轴数按 **3 → 4 → 2 累积**（不是每次都归 1）。
- **修复**：在 delaxes **之前**先断掉 `ax._colorbar` 关联，让 colorbar 的独立 Axes
  能被正常删掉；delaxes 循环与 clf() 的顺序**保持与旧实现一致**。
- **踩坑记录（重要）**：第一版改成了「先 `cb.remove()`，再只 `clf()`」，功能上
  能把轴清空，但回归 `t_window_lifecycle` **报失败**：
  `GC 后主窗口控件仍未释放：1736 → 782`。逐个变体二分后定位到
  ——`clf()` 单独使用会让 Axes 对象被 GC **延迟回收**，前面 70 项测试累积后
  控件数越线；而 `cb.remove()` 又额外制造了一层 Colorbar↔Axes 引用。
  最终采用「先断 `_colorbar` 引用 → 保留原 delaxes 序列 → clf() 收尾」，
  既清得干净、又不改变既有 GC 行为（回归恢复 71/71）。
- 实测：轴数每轮恒定 `[2,2,2,2]`（1 个 3D + 1 个 colorbar），
  交替 3D↔等高线五轮，违规项 0。

### 3D 曲面 colorbar 只有 14px 宽，刻度读不出

- **现象**：3D 曲面图右侧的色标窄成一条，刻度数字完全挤在一起、
  看不懂颜色对应什么强度；右侧还空着一大块。
- **根因**：`colorbar(shrink=0.55, aspect=18, pad=0.10)` —— `aspect=18` 把色标
  压成极窄条，`shrink=0.55` 又让它只占半高。
- **修复**：改为 `shrink=0.85, aspect=12, pad=0.06`，右边距 0.86 → 0.93。
- 实测：colorbar 宽 **14 px → 32 px**（跨过"刻度可读"的 30px 门槛）。

### 3D 曲面 z 轴标签与 colorbar 重复且互相压字

- **现象**：z 轴写「强度 (AU)」、colorbar 也写「强度 (AU)」，两个标签只隔几十像素，
  3D 视角下「强度」两个字被色标压住一半。
- **修复**：z 轴不再设标签（`set_zlabel('')`），量名与单位统一由 colorbar 承担
  ——colorbar 的 label 才是"刻度数值对应什么"的正规去处。

### 等高线 / 3D 曲面的 EM 轴方向反惯例

- **现象**：EEM 图上 EM 波长是「大波长在下、小波长在上」，与文献和仪器软件
  （Horiba / Edinburgh 的 EEM 视图）**相反**。用户读图要先在脑子里翻一次，
  很容易看错峰位归属；而且等高线与 3D 曲面的朝向还不一致，切换视图时"跳一下"。
- **根因**：`draw_contour()` 与 `draw_surface()` 里各有一次 `ax.invert_yaxis()`。
- **修复**：两处都删掉。EEM 的通行画法是 EX 向右、EM 向里/向上**都随波长增大**，
  这样 Rayleigh/Raman 散射脊线是单调斜向条纹，一眼能认。
- 实测：等高线 EM 轴范围 `(900, 200)` → `(200, 900)`，方向已常规。

## ✅ 验证

| 项目 | 结果 |
|---|---|
| 回归测试 | **71 / 71 通过**，0 失败 |
| `clear_fig` 轴数 | 每轮恒定 `[2,2,2,2]`（修复前 3→4→2 累积） |
| 3D↔等高线交替 5 轮 | 违规项 0（3D 时恰好 1 个 3d 轴、2D 时 0 个） |
| colorbar 宽度 | **14 px → 32 px** |
| 等高线 EM 轴 | `(900,200)` → `(200,900)`，常规方向 |
| 3D 曲面 EM 轴 | 同步改为常规方向 |
| z 轴标签 | 已移除（避免与 colorbar 重复/压字） |
| 全部改动 `py_compile` | 通过 |

**一处回归失败的排查记录**（值得留档）：这批改动中途 `t_window_lifecycle` 连续失败三次，
我依次排除了 `plot_3d_scan.py`、`gui_plot.py` 的嫌疑，最后用「只回退 clear_fig」确认是它，
再用四个变体（旧实现 / 只 clf 优先 / 完整新版 / 断引用+原序列）逐一定位到
`clf()` 单独使用会让 GC 延迟回收 Axes。教训：**改清理逻辑时要连"对象回收时序"一起验**，
不能只看"功能是否清空"。
