## 🔴 τ 范围不足导致寿命算错 65.9 倍，而错值看起来完全正常

### 现象

`示例数据\03-荧光寿命-Ce6` 实际上是 **μs 级磷光**（1O₂ 的 1270 nm 发射这一类），
而 GUI 默认 τ 范围是 0.01–100 ns：

| 设置 | 报出的 τ | χ²R | 质量标记 |
|---|---|---|---|
| **默认 0.01–100 ns** | **85.8 ns** | **75.5** | poor |
| 放宽到 1e6 ns | 5653 ns | 2.77 | ok |
| 自动建议范围 | 5513.9 ns | 2.765 | ok |

**相差 65.9 倍。** 而 `85.8 ns` 这个错值落在默认范围内、量级"合理"，
用户会**直接抄进报告**——这正是它最危险的地方。

### 根因

熵分布的最慢端被网格端点（100 ns）卡住，全部强度堆在边界上，
报出来的 τ 只是「网格能表示的最大值」，不是拟合出的寿命。

程序**其实早就算出了铁证**：`intensity_share_slowest_decade = 100%`
（全部强度堆在最慢的十分位）。但 GUI 只在拟合完成后给一句
"建议放宽 τ 范围复算"，且 **τ 值本身在分量表 / CSV / MD / PDF 里一字不改**。

### 修复

**① 新增 `plot_lifetime.suggest_tau_range()`**（约 70 行，纯 numpy）

从数据本身推断合理范围：

- **下界** τ_min = `max(IRF_FWHM/10, 3×通道间隔, 1e-3 ns)`
  ——比 IRF 窄得多的分量本来就无法从卷积里解出；
- **上界** τ_max = `max(3×峰后窗口长度, 100×τ_min)`
  ——系数 3 是给分布留拖尾空间，紧贴窗口末尾会再次造成边界堆积。

返回值含 `reason` 字段（通道间隔 / IRF FWHM / 峰后窗口），界面上直接说明依据。

**② 新增 `plot_lifetime.tau_range_complaint()`**（约 20 行）

按 `intensity_share_slowest_decade / fastest_decade > 0.5` 判定范围是否明显不够，
返回人话理由。**不用 `intensity_share_grid_edges`**：后者在默认范围下只有
51.66%、正确范围下 0%，区分度不够；十分位判据则是 100% vs 0%，干净得多。

**③ GUI 三处接入**

- 信息页（`_show_lifetime_info`）：加载数据时即给出建议范围，当前设置不覆盖时**当场警告**并说明后果；
- 参数栏新增「**采用建议范围**」按钮：一键填入，省得用户自己算；
- 拟合信息页（`_show_lifetime_fit_info`）：范围不足时把结论升格为
  **"❌ 结果不可信"**，并明确写「在修正之前不要使用这组 τ / 占比数据」，
  不再只是一句轻飘飘的"建议放宽"。

### 验证

| 情形 | 判据输出 | 期望 |
|---|---|---|
| 默认 0.01–100 ns（slowest=100%） | 报警 | ✅ |
| 手动放宽 1e-3–1e6 ns（slowest=0%） | 不报警 | ✅ |
| 自动建议范围（slowest=0%） | 不报警 | ✅ |
| τ_min 一侧堆积（fastest=100%） | 报警 | ✅ |

自动建议与手动放宽的 τ 相差 2.46%（网格离散所致），χ²R 2.765 vs 2.774。

## 🔴 寿命衰减文件被「发射光谱」模式静默当成光谱读入

### 现象

把 `Ce6 lifetime.csv`（400 µs 衰减曲线）放进发射光谱模式：

```
label  = 'Ce6 (Time Scan)'
x 范围 = [0, 3.999e+05]      ← 单位其实是 ns，被标成 "波长 (nm)"
_load_errors           = 0 条
弹窗                    = 0 条
```

用户拿到一张**看起来完全正常**的"发射光谱图"，纵轴是光子计数，
横轴是时间——没有任何提示说这不是光谱。

### 根因

`plot_emission.detect_format` 用
`'Fixed/Offset' in head and 'XAxis' in head` 判定 flwinlab 格式，
而 Horiba/DeltaHub 的衰减文件 header 同样含这两个字段：

```
Type,Time Scan,Instrument Response Time Scan      ← 已经写明
Fixed/Offset, ,
XAxis,Time(ns),Time(ns)                           ← 已经写明
```

`parse_flwinlab_csv` 把 `xaxis`、`spectrum_type` 都读出来了，**却没有任何地方消费**。
于是"前两列都是数值"的行全被当成光谱点。

### 修复

- 新增 `plot_emission.detect_decay_file()`：读文件头 60 行，命中
  `XAxis,Time/Temp/Channel` 或 `Type,Time Scan/Decay/Lifetime/Phosphorescence Decay`
  即判为时间扫描数据，**并返回命中的原文作为证据**；
- `parse_csv()` 在选解析器之前先拦，抛错并明确指向「荧光寿命」模式；
- `detect_format()` 的 `XAxis` 判据改为同时接受 `Xaxis`（**顺带修掉审计 D-M2**：
  真实 PerkinElmer 导出用小写 `Xaxis`，旧判据大小写敏感）；
- `load_spectra()` 新增 `errors` 参数，把每个失败文件的原因带回去
  ——此前原因被直接丢弃，GUI 只能报"跳过 N 个"却说不清为什么。

### 验证

| 检查 | 结果 |
|---|---|
| 衰减文件被识别并给出证据 | ✅ `'Decay'` |
| `load_spectra` 不再返回伪光谱 | ✅ 0 条，原因已记录 |
| 提示指向寿命模式 | ✅ |
| 正常发射光谱不受影响 | ✅ 1 条 |
| PerkinElmer（`Xaxis` 小写）能解析 | ✅ **4/4 个**（修复前 0/4） |

## 🟡 Ctrl+T 到不了「高对比」主题（改 1 行）

### 现象

帮助（`gui_ui.py:1076`）和主题按钮 tooltip 都写着
「循环切换三套主题（浅色 → 深色 → 高对比打印友好）」，
但实测 **Ctrl+T 序列是 `light→dark→light→dark`**——永远到不了第三套。
只有用鼠标点按钮才是三态循环。

### 根因

`gui_ui.py:300` 绑的是 `toggle_theme`（v4.30 之前的两态兼容层），
而按钮绑的是 `cycle_theme`。后者的 docstring 自己就写着
「主题按钮 / **Ctrl+T**：三套主题循环切换」——说明原本就该这样绑，
是 v4.30 改造时漏改了这一处。

### 修复

```diff
- ("Ctrl+T", lambda: self.toggle_theme()),   # E5：切换主题
+ ("Ctrl+T", lambda: self.cycle_theme()),    # E5：切换主题（三态循环）
```

### 验证

实测序列 `light → dark → contrast → light`，纯循环无重复。
