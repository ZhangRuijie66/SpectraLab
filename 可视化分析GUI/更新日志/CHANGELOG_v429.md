## 一、三栏改成真正的停靠面板（QDockWidget）

原来「目录树 / 数据 / 参数」三栏是 `QSplitter` 的三个子控件——只能拖分隔条改宽度，
不能浮动、不能换位、不能叠放。本版改成 `QDockWidget`：

| 能力 | v4.28 及以前 | v4.29 |
|---|---|---|
| 改宽度 | 拖分隔条 | 拖分隔条（同前） |
| 收起 / 展开 | 左侧栏开关条按钮 | 栏开关条按钮 **或** 标题栏的 **✕**（两条路都同步） |
| 拖出成浮动窗口 | ✗ | ✅ 拖标题栏即可拖出，成为独立窗口（可放到第二块屏） |
| 左右换边 / 两栏互换位置 | ✗ | ✅ 直接拖 |
| 叠成标签页 | ✗ | ✅ 一栏拖到另一栏上即可叠放，点标签切换 |
| 标题栏 | 分组框自带标题 | 主题化标题栏 + 关闭/浮动按钮（深浅两套单色图标） |

- **画布成为中央部件**：三栏收起后画布自动吃满整个窗口（不再有"留白的三栏位"）。
- **栏开关条保留**：它固定在窗口最外侧（改成左工具条区域里的 `QToolBar`），
  栏被关掉后仍然能点回来——这是 v4.26 定的规矩，dock 化之后更要守住。
- 面板本体的圆角卡片样式跟着主题走：标题栏画上半部分圆角、面板画下半部分，
  中间不描边，视觉上仍是一张完整卡片（深浅两套都验证过）。

## 二、三套布局预设（一键切换工作状态）

左侧栏开关条下方新增 **「布局」** 按钮（下拉菜单），三个预设：

| 预设 | 快捷键 | 效果 | 适用 |
|---|---|---|---|
| **拟合工作台** | `Ctrl+1` | 三栏全开，参数栏加宽到 320px | 边调参数边看拟合结果（默认） |
| **出图工作台** | `Ctrl+2` | 收起参数栏，宽度让给画布 | 专心出图 / 批量导出 |
| **只看图** | `Ctrl+3` | 三栏全部收起，画布铺满窗口 | 汇报、审图、投影 |

菜单里还有：三个栏各自的显隐勾选（与栏状态自动同步）、**「恢复默认布局」**
（把拖乱/浮动/叠放的栏一键归位到「左侧 目录树+数据、右侧 参数」）。

## 三、停靠状态记忆

- 关窗时把整套停靠状态（浮动 / 换位 / 叠放 / 各栏宽度 / 收起状态）存进 `QSettings`，
  下次启动原样恢复。
- 状态带**版本号**（`ui/dock_state`，版本 1）：以后若增删或重命名面板，只要把版本号 +1，
  旧设置会被安全忽略，不会读回坏布局。
- 各栏宽度仍然单独记忆（`ui/panel_widths`），并且只在**用户真的拖动分隔条**时才记录
  （窗口缩放导致的连带变窄不算，避免"窗口拖小一次"就永久把栏宽改小）。

## 四、⚠️ 本版修掉的两个硬崩溃（重点）

这两个都是 dock 化过程中踩出来的，属于**会带走整个进程**的严重问题，已修复并加了回归守卫：

**1）给 dock 接 `visibilityChanged` 会 abort（退出码 0xC0000409、无任何 traceback）**

- 原因：`dock.visibilityChanged.connect(lambda ...)` 的闭包引用 `self`，与 dock 形成引用环，
  窗口对象不再即时析构、被 GC 延后到任意时刻销毁；而**仍处于显示状态**的窗口在析构时
  dock 会发 `Hide` 信号，PyQt5 在析构期派发这个信号直接 abort。
- 表现：连开 3 个窗口必崩；回归测试跑到一半静默死亡。
- 修法：改用 `installEventFilter` 听 dock 自己的 `Show`/`Hide` 事件（事件过滤路径在析构期
  安全，也不产生引用环）。
- **哨兵**：新增回归项「主窗口反复建/销毁不泄漏、不在析构期崩」——删窗口后强制 `gc.collect()`
  逼出析构，正是当初崩掉的那条路径。

**2）`QApplication.setStyleSheet` 重复下发导致访问违例（退出码 0xC0000005）**

- 原因：应用级样式表每建一次窗口就重设一遍，Qt 会重新解析整张表并对进程内**每一个**控件
  unpolish/polish；在"旧窗口还没被 GC 回收、又新建窗口"的场景下，实测第 47~48 个窗口
  必崩在 `app.setStyleSheet` 这一行。
- 修法：样式表内容与当前已生效的一致时直接跳过（内容没变就是纯浪费）。

## 五、顺带修掉的测试可靠性问题

回归测试里有十几项依赖"上次会话"的状态（栏宽/收起、上次模式、上次主题、寿命默认值）。
以前它们中途失败或进程被强杀时，自己的 `finally` 恢复逻辑不一定会跑到，残留值会让
**下一次**回归跑出完全不同的结果（这次排查连续踩到三回：`last_mode=2` 让「状态栏徽标」失败、
`theme=dark` 让「主题图标切换」失败、`ui/panel_widths=[5,99999,285]` 让栏宽检查失败）。

现在 `run_regression.py` 在开跑前**统一把这些会话键"借走"**（`ui/` `defaults/` `param/`
`help_dialog/` 前缀 + `last_mode` `last_folder` `theme` `workspace` `recent_folders`），
跑完原样放回。实测：完整跑一遍回归后注册表**零变化**（不增、不丢、不改），
用户真实设置也不会被测试改掉。

## 八、备注

- **操作路径**：左侧栏开关条 →「布局」按钮；或快捷键 `Ctrl+1/2/3`。
  想拖出浮动窗口：直接拖某栏的**标题栏**往外拖。
- 参数栏、数据栏的**内容与原来完全一致**（控件、顺序、默认值都没动），
  只是外面套了一层可停靠的壳。
- 若把三栏都拖乱了，菜单里点「恢复默认布局」即可归位。
