## 🌙 跟随系统深色模式（用户反馈）

### 入口门户首次启动是白界面

- **现象**：Windows 深色模式（`AppsUseLightTheme=0`）的用户第一次打开程序，
  入口门户、启动画面、主窗口**全是浅色**。而且此后每次启动都从
  `QSettings` 读保存的主题，等于**永远停在浅色**——用户得先手动按 Ctrl+T 一次
  才会被记住。
- **根因**：`DEFAULT_THEME = "light"` 是硬编码常量，程序**从不读取操作系统的
  深浅色设置**；`saved_theme()` 在没有保存值时也回退到 `light`。
- **修复**：
  - `gui_config` 新增 `detect_system_theme()`，三平台分别读：
    Windows 注册表 `Personalize\AppsUseLightTheme`（0=深色）、
    macOS `defaults read -g AppleInterfaceStyle`、
    Linux `gsettings ... color-scheme`；任何一步失败都退回 `light`（绝不让探测异常影响启动）。
  - `gui_launcher.saved_theme()` / `gui_splash.saved_theme()` /
    `gui_data._restore_session()` 在**没有保存过主题时**改用系统探测值。
  - `AbsorptionGUI.__init__` 提前设好 `self.theme` 初值——此前 `setup_ui()`
    先按默认主题画一遍、`_restore_session()` 再重画，深色用户会看到**白闪**。
- 实测：系统深色下，门户 / 启动画面 / 主窗口 / 帮助窗口首次启动**全部为深色**；
  用户手动选过浅色后，后续启动一律尊重用户选择（不会被系统覆盖）。

## ⚡ 批量导出搬进后台线程（P1）

- **现象**：40 个文件 PNG+PDF 在主线程里逐张渲染 + `savefig`，实测 **18.17 s**，
  期间事件循环存活率只有 **11%**（最长 538 ms 无响应），且**完全不可取消**
  （`export_all_plots` 里 `cancel` 出现 0 次）。
- **修复**：
  - 新增 `_collect_export_params()`：主线程把全部控件值读成快照
    （后台线程不能碰 Qt 控件）；
  - 新增 `_do_export_all()`：后台执行全部渲染与落盘，进度经
    `PlotWorker.report` 上报、取消经 `worker.is_cancelled()` 轮询；
  - 复用 v4.45 的 `_start_worker`，因此自动获得状态复位与代次校验；
  - 新增 `_on_export_all_finished()` 回调（含过期代次丢弃）。
- **线程安全**：导出用的 Figure 改用 `Figure()` 直建 + `add_subplot(111)`，
  不走 `plt.subplots()`。后者会走 pyplot 的 GUI 后端（本项目是 Qt5Agg），
  在非主线程里会触发 matplotlib 警告
  *"Starting a Matplotlib GUI outside of the main thread will likely fail"* 并有崩溃风险。
  配套新增 `_dispose_fig()`：对非 pyplot 托管的 Figure 调 `plt.close()`
  会报错，这里按类型兜底（close 失败就 clear）。
- 实测：最长单次无响应 **538 ms → 45 ms**，导出期间事件循环正常处理事件，
  取消后状态正确复位且可继续操作。

## 🎨 徽标三档对比度全部达标（P1）

- **现象**：拟合质量徽标 ok/warn/bad 的文字用的是 `SUCCESS`/`ORANGE`/`DANGER`
  本色，压在**同色系的浅底**（`*_BG`）上，全部不到 WCAG 4.5:1：
  light 下 3.00 / 3.11 / 3.95，dark 下 4.27 / 4.14 / 3.62 —— 药丸上的字读不清。
- **修复**：文字与边框改用深一档的 `*_HOVER`；`bad` 档新增专用令牌
  `DANGER_TEXT`（light `#b91c1c`、dark `#fca5a5`、contrast 沿用 `#a80000`）。
- 实测（三套主题 × 三档）：

| 主题 | ok | warn | bad |
|---|---|---|---|
| light | 3.00 → **4.57** | 3.11 → **4.52** | 3.95 → **5.30** |
| dark | 4.27 → **5.58** | 4.14 → **5.56** | 3.62 → **5.28** |
| contrast | 6.25 → 8.56 | 6.48 → 8.64 | 6.07（已达标） |

三套主题键集合仍完全一致（50 个），回归里那条守键一致性的测试照常通过。

## 📊 26 条曲线：颜色不再重复、图例不再重名、峰标注不再糊成一片（P1）

这一节是连着的三个问题，示例数据 `05-数据比较-浓度梯度` 一条路径就能全撞上。

### 颜色只有 9 种（Set1 用尽后循环复用）

- **修复**：`CurveColors.get()` 增加 `total` 参数。总数超过色表唯一色数时，
  自动把离散色表插值成**连续色带**（`LinearSegmentedColormap`，N=256）。
- **踩坑记录**：第一版用 `ListedColormap`，它的 `N` 等于采样点数（9），
  分配器仍按"离散色表"处理，颜色照样重复（实测仍 9/26）。必须显式给 N=256。
- 实测：26 条曲线 **9/26 → 26/26** 互不相同（Set1 与 tab10 都验证）。

### 图例 26 条只有 8 条唯一标签

- **根因**：合并图为了简短，说明.xlsx 匹配成功时**只显示说明信息、不显示样品名**。
  一批同类样品（比如都是「RB浓度=50」、只是测量次序不同）就得到多条相同标签。
- **修复**：新增 `_legend_labels_for()` 批量生成标签——发现重复时补样品名后缀
  （`RB浓度=50 (EX=450 nm) [20260915-03#RB_Emission]`），二次兜底用序号强区分。
- 实测：26 条 → **1 条唯一 → 26 条唯一**。

### 图例盖住整张图 + 峰标注 188 对重叠

- **现象**：图例固定 9pt、单栏、坐标区内；26 条时变成一整块盖住几乎全部数据区
  （实测占坐标区 35%+，标签溢出画布外）。峰标注则在每条曲线都标 500 nm，
  26 个数字堆在同一处。
- **修复**：
  - `_apply_legend` 按条数分档：≤6 条原样；7–12 条 8pt 两栏；
    **>12 条强制外置到坐标区右侧**、多栏、7.5pt。配套 `_legend_outside_by_count()`
    让 `subplots_adjust` 放宽右边距（right 0.98 → 0.72），避免外置图例被裁掉。
  - 峰标注：曲线 >6 条时**只标最强那条曲线的峰**，并加粗。
    注意判据是「整体只标一条曲线」而非「每条曲线少标几个峰」——
    每条曲线通常就一个峰，后者根本减少不了标签总数（第一版就写错了，
    截图 diff 为零才发现）。
- 实测：26 条时峰标注 **26 个重叠 → 1 个清晰**；图例外置不遮挡。
