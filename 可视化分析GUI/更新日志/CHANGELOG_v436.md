## 🐛 修复：启用「光谱减法」之后无法积分（积分结果表整张空掉）

**症状**：勾选「启用光谱减法」、A =「所有光谱（各减本底）」、B = 某条本底之后，
图能正常画出来，但下方「光谱积分（数据输出）」的结果表**一行都没有**，
计数标签也没有任何解释——看起来就像"减法开着就不能积分了"。
（2026-09-15 那批数据实测：`1#RB-2 / 1#RB / 2#R101-2 / 2#R101 / EtOH / H2O`，
B 选 `H2O (Emission)`，积分区间 400–510 nm。）

**根因**：两条独立的问题叠在一起。

1. **积分把异常整个吞了。** `gui_plot.py::_compute_integration_results` 里逐条调用
   `_get_plot_xy()`，后者在启用减法时会走 `_subtract_ref()`；只要**任何一条**光谱
   与本底的波长范围没有重叠，`_subtract_ref` 就抛 `ValueError`。这个异常冒到
   `_do_plot()` 里被 `except Exception` 接住，只写了一条 `logging.warning`，
   然后把 `_last_integration_results` **整个置成 None** → 结果表清空。
2. **积分扫的是"所有已加载样品"，不只看勾选的那些。** 所以哪怕用户只勾了一条
   能扣本底的光谱在画图（图上只画这一条），积分仍然会去碰那些**根本没在图上**
   的样品（如 560–800 nm 的 R101、EtOH），照样被第 1 条的异常掀掉整张表。

那批数据的真实波长范围（不是解析错误，是实测用不同发射窗口测的）：

| 文件 | 波长范围 | 与本底 H2O (300–548 nm) |
| --- | --- | --- |
| 1#RB-2 | 300–540 nm | 重叠 → 可扣本底 |
| 1#RB | 360–500 nm | 重叠 → 可扣本底 |
| 2#R101-2 | 560–800 nm | **不重叠 → 无法相减** |
| 2#R101 | 575–800 nm | **不重叠 → 无法相减** |
| EtOH | 560–800 nm | **不重叠 → 无法相减** |
| H2O（本底） | 300–548 nm | 本底自身不参与积分 |

顺带一提，同样的异常在**绘图**路径上也会发作：`_plot_emission_combined` /
`_plot_combined` 里 `_get_plot_xy()` 是裸调用，所以"勾上全部 6 条 + 开减法"
会直接弹「绘图失败: 本底「H2O (Emission)」与数据波长范围无重叠，无法相减」，
整张图都出不来。用户当时只勾了一条，所以只看到"不能积分"。

**修复**：新增宽容取值口径 `_get_plot_xy_checked()` —— 扣不了本底的那一条
**只跳过自己**，并记入 `_subtract_skipped`，其余光谱照常绘制/积分。

- **积分侧**：`_compute_integration_results()` 逐条 try，返回值多一个
  `skipped = [(样品名, 原因)]`；结果表照常填能算的那些行，不再整表清空。
  计数标签写「共 2 个样品 · 400–510 nm（3 个无法扣本底已跳过）」，
  把鼠标停在标签上可看**是哪几条、什么原因**；一条都算不出来时提示
  「无可用积分结果（N 个无法扣除本底，见悬停提示）」而不是无声空表。
  差谱模式（A − B）无重叠时同样只提示、不抛异常。
- **绘图侧**：`_plot_combined` / `_plot_emission_combined` 跳过扣不了本底的那条，
  状态栏补一句「图表更新完成；已跳过 3 条无法扣除本底的光谱（……，波长范围与本底无重叠）」；
  单独图把原因**写在画布中央**（与差谱无重叠时的表现一致），不再弹「绘图失败」。
- **导出侧**：导出单图时这一条进失败明细并写明原因；导出合并图时跳过它，其余照常。
- **UI 文案**：「光谱减法」分组加 tooltip 说明该行为；积分表 tooltip 写明
  积分覆盖**所有已加载样品（与勾选无关）**、且按扣本底后的曲线积分；
  用户手册 6.3 节同步。

## ✅ 回归测试

新增 `GUI：减法扣不了本底的光谱只跳过自己，不再清空积分表/整图报错（v4.36）`：
造 4 条合成光谱（A、B 与本底 300–548 重叠，C 为 560–800 完全不重叠，外加本底），
断言

- 启用减法后 `_last_integration_results` **不为 None**（修复前必为 None）；
- 结果行恰好是 `['A', 'B']`、积分值有限，`skipped` 里 `C` 的原因含「无重叠」；
- 结果表 2 行、计数标签含「共 2 个样品」与「1 个无法扣本底已跳过」、悬停提示里有 `C`；
- 图上恰好 2 条曲线（跳过的那条不画）、状态栏含「已跳过 1 条」；
- 差谱模式 A=C 时结果为空但只记录跳过、不抛异常；
- 关掉减法后口径回到 4 条样品、`skipped` 为空（C 因与积分区间无重叠为 NaN，
  仍由结果表按「无重叠未列出」处理）。

全套回归：**60 项：通过 55 / 跳过 3 / 失败 2**。这 2 项失败（`GUI：空状态插画…（v4.31）`、
`GUI：状态栏进度条 + 模式/样品数徽标（v4.27）`）与本次改动无关——是**本机沙箱注册表只读**
（`QSettings.isWritable() == False`，同因导致 3 项 SKIP）让会话偏好写不进去、`last_mode`
读回旧值造成的。已用 `git worktree` 拉出 v4.35 基线跑同一套回归对照确认：基线同样是
**59 项：通过 54 / 跳过 3 / 失败 2**（同样的两项）。
