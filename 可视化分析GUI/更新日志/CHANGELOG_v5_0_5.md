## 🔴 参数栏滚轮陷阱：想往下滚，结果把参数改了

### 现象

参数栏是一条必须滚动的长列表（1280×800 下吸收模式要滚 **680 px ≈ 2.12 屏**）。
而 Qt 的滚轮响应**不看 focusPolicy**——只要指针恰好落在下拉框/数值框/滑块上，
滚一格就改值，**面板却一动不动**：

| 指针停在哪 | 滚一格的结果 |
|---|---|
| 「图表类型」下拉框 | 「合并图」→「单独图」，**整张图重画** |
| 「线宽」数值框 | 1.5 → 1.4 |
| 「线宽」滑块 | 14 → 11 |

**而且没有任何提示**，用户只会觉得「图怎么自己变了」。

### 量化

```
参数栏视口        255×687 = 175185 px²
滚轮敏感控件覆盖          50771 px²  = 29.0%
每滚一屏，约三成滚动路径会误改参数
```

全项目检索 `wheelEvent` / `QWheelEvent` 滚轮拦截：修复前 **0 处**。

### 修复

在 `gui_ui.py` 新增 `WheelGuard`（事件过滤器），装到参数栏全部滚轮敏感控件上：

- **未聚焦 + 滚轮** → 事件转交给 `QScrollArea` 的 viewport，面板正常滚动，控件值不变；
- **已聚焦 + 滚轮** → 保持原生行为，滚轮照常调值。

第二条是关键：聚焦后滚轮调数是这类控件的**正当用法**，一并禁掉就是修好一个坑
又挖一个。实测聚焦后数值框仍能 1.5→1.4、下拉框仍能 0→1。

**装好 37 个控件**（QComboBox 13 / QAbstractSpinBox 16 / QSlider 8）。

## 🔴 界面中英混排：53 个弹窗的标准按钮全是英文

### 现象

程序界面全中文，但所有系统级按钮是英文——确认框是 `&Yes` / `&No`
（还带 Windows 助记符 `&`），错误框是 `OK` / `Cancel`。用户在一句中文提示
「拟合尚未完成，关闭窗口将中止本次拟合并放弃本次结果。确定关闭？」
下面看到的是两个英文按钮。

更割裂的是：`QFileDialog` 走系统原生对话框（**中文**），
于是同一个程序里**文件框中文、确认框英文**。

### 根因

```
QLocale.system()                                = zh_CN
QApplication.translate("QPlatformTheme", "OK")  = 'OK'       ← 未翻译
Qt 翻译目录里可用的 qtbase_zh* = ['qtbase_zh_TW.qm']         ← 只有繁体
```

PyQt5 wheel **只带 `qtbase_zh_TW.qm`、不带 `qtbase_zh_CN.qm`**，
所以「装 .qm 文件」这条路走不通。全项目 `installTranslator` 调用：**0 次**。

### 修复：用内存 QTranslator，而不是改 53 处调用点

新增 `gui_i18n.py`：

- `ZhStandardButtons(QTranslator)`：覆盖 Qt 内置标准按钮文本（Ok/Cancel/Yes/No/
  Save/Discard/Close/Apply/Reset/Abort/Retry/Ignore/Open/Help… 含带 `&` 助记符的形态）；
- **未命中返回空串**（`QTranslator` 约定 = "我没译，走原逻辑"），
  所以「自定义按钮文字」「Process」「Export」这类文字不受任何影响；
- `install_zh_standard_buttons(app)`：幂等，重复调用返回同一实例。

**为什么不用改调用点**：53 处 `QMessageBox.*` 逐个改成 `addButton("确定")`，
改动面大、要为每处想按钮文字、还要处理默认按钮与返回值；装一个 translator
只需一处代码，且所有标准按钮（含 `QDialogButtonBox`、未来新增的调用点）一起生效。

### 四个入口都要装（关键疏漏点）

`main()` 里装了还不够——**`start_gui.py` 与 `launch_hidden.py` 直接构造
`AbsorptionGUI`，不经过 `main()`**，而 `launch_hidden.py` 正是**桌面快捷方式
实际走的路径**。不在这两处补装，从快捷方式启动时按钮还是英文。

| 入口 | 是否经过 main() | 处理 |
|---|---|---|
| `entry_gui.py` → `absorption_gui.main(app=...)` | ✅ | main() 内安装 |
| `absorption_gui.py` 直接运行 | ✅ | main() 内安装 |
| `start_gui.py` | ❌ | 单独安装（在 `ModuleLauncher` 之前，入口界面自己也会弹框） |
| `launch_hidden.py`（**桌面快捷方式**） | ❌ | 单独安装 |

## ⚠️ 一个过程中的坑（记录备查）

给 `打包便携版.ps1` 加 `--hidden-import gui_i18n` 时，编辑工具**吃掉了文件的
UTF-8 BOM**——而 PS 5.1 会按 GBK 解析无 BOM 的脚本，导致中文全部乱码。

已用 `UTF8Encoding($true)` 恢复，并确认 `git diff` 里不再出现 BOM 的增删
（修复前后 diff 只有新增那一行 `+    "--hidden-import","gui_i18n",`）。

**教训**：编辑 `.ps1` 后必须核对前 3 字节是否为 `239,187,191`。
Python 文件则相反——必须是**无** BOM（`gui_config.py` 本次用 edit 工具改，
前 3 字节 `35,32,45` = `# -`，正确）。
