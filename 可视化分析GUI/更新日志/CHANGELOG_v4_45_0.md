## 🔴 修复：后台任务状态机（三处 P0）

### `_plotting` 泄漏 → 实时预览永久失效且无提示

- **现象**：`_run_overlay_lifetime` / `_run_batch_export` 把 `self._plotting = True`
  写在 `try` **之外**。一旦线程启动阶段抛异常（线程对象创建失败、参数收集出错等），
  `_plotting` 就永久停在 `True`：此后 `update_plot` 在开头直接 `return`，
  **实时预览彻底失效、没有任何提示**，用户只能重启程序。
- **修复**：抽出统一启动器 `_start_worker()`，`_plotting` 的置位与复位全部由它接管，
  异常路径必定复位并递增代次作废在途结果。
- 实测：注入「线程对象创建失败」后 `_plotting` 正确回落到 `False`，
  随后 `update_plot` 仍能正常绘图（旧实现此后永久失效）。

### 取消超时后线程成孤儿，把旧结果画到新模式的界面上

- **现象**：`_cancel_plotting` 只 `wait(5000)`。超时后线程仍在跑，算完后照样回写
  画布与 `_last_*_result`——实测切到吸收模式后，**寿命拟合图被画到了吸收模式的画布上**。
- **修复**：引入**代次（generation）**机制：
  - `_cancel_plotting` 先 `_bump_generation()` 让在途结果失效，再尝试停线程；
  - 所有完成回调（`_on_plot_finished` / `_on_overlay_finished` /
    `_on_batch_export_finished` / `_on_plot_error`）开头校验代次，不匹配就丢弃。
  这样即使 `wait` 超时、线程还在跑，它的结果也**永远不会**被应用到界面上。
- 实测：取消耗时 **118 ms**（旧实现最坏冻结 5000 ms）；过期结果回放时画布零改动。

### 批量拟合「取消」按钮无效

- **现象**：`fit_many` 签名里没有 `cancel_cb`，而 GUI 侧只在 **全部返回之后**才检查
  取消标志——点取消后 7/7 个样品照样全部算完，用户干等全程。
- **修复**：`plot_lifetime.fit_many` 增加 `cancel_cb` / `progress_cb`：
  - 提供 `cancel_cb` 时改为**分批串行**提交（每批 `max_workers` 个），批间检查取消标志，
    已开始的算完、未开始的直接跳过（结果为 `None`，如实上报）；
  - 中途中断时 `shutdown(cancel_futures=True)` 撤销排队任务；
  - `progress_cb(done, total)` 每完成一个样品回调一次，解决「进度信号最大间隔 9.78 秒」。
  - GUI 侧把 `worker.is_cancelled` / `worker.report` 传下去。
- 实测：立即取消 → **0/6** 启动；拟合 1 个后取消 → 成功 1、跳过 5；结果长度与输入同序。

## 🔴 修复：导出两套渲染逻辑不一致（P0）

### 「导出当前图」与「导出全部」得到两张不同的图

- **现象**（三个具体表现）：
  1. **合并图导出永远没有峰标注**——`_render_combined_export_fig` 签名里根本没有
     `mark_peaks`，`export_all_plots` 在 `:2841-2843` 读了三个峰参数却只喂给单图；
  2. **导出图丢失显示范围**——画布 500–600 nm，导出却是全谱 361–926 nm；
  3. **单栏 3.5 in 预设超宽 15%**——「导出当前图」直接 `savefig(canvas.fig)`，
     而画布 fig 是按屏幕尺寸建的、字号停在界面字号（`_apply_pub_rc` 只影响**此后新建**
     的 fig）。选了单栏预设后被 `set_size_inches(3.5, 2.6)` 硬塞、字号仍 13pt，
     `bbox_inches='tight'` 一膨胀变成 **4.013 in**，投稿排版放不进；同样操作
     「导出全部」走重画路径得到 3.508 in（正确）。
- **修复**：
  - `_render_combined_export_fig` 补 `mark_peaks` / `peak_height` / `peak_distance` / `xlim`；
  - `_render_single_export_fig` 补 `xlim`；
  - `export_all_plots` 把这些参数都传下去；
  - 新增 `_make_current_export_fig()`：「导出当前图」在预览页也走**同一条重画路径**，
    画布只当预览、不当导出源。其它页（数据比较 / 诊断 / 寿命分布）没有独立渲染器，
    仍存画布 fig——重画失败时也回退画布（宁可尺寸不准，也不要导不出图）。
- 实测：两条路径的峰标注（3 vs 3）、显示范围（均 500–600）、物理尺寸
  （均 **3.507 in**，修复前 4.013 in）全部一致。

## 🟠 修复：会话状态（两处）

### τ 不变量被破坏：界面显示 τ_min == τ_max，实际拟合却用默认范围

- **现象**：会话恢复时 `_restore_session` 批量 `setValue`，此时 `sender()` 为 `None`，
  `_sync_lifetime_tau_range` 会误判成「改的是 τ_min」，把 τ_max 抬成 `lo*10`；
  当两个值恰好相等（如都 0.001）时谁也拆不开，最终停在
  **τ_min == τ_max == 0.001**。此后 `_collect_plot_params` 发现非法就**静默回退
  默认 0.01–100 ns** —— 界面显示的范围与实际拟合用的范围不一致，用户完全看不出来。
- **修复**：
  - `_sync_lifetime_tau_range`：`sender()` 为空（非用户操作）时按「哪个值越界」决定
    让路方向；仍解不开时按 10 倍拉开；末尾加兜底复查，保证**严格** τ_min < τ_max；
  - `_restore_session` 恢复顺序改为**先 τ_max 后 τ_min**，从源头避免互踩。
- 实测：恢复越界值后界面显示 `τ_min=0.001 < τ_max=0.01`，且
  `_collect_plot_params` 返回的正是这组值（不再静默回退）。

### 加载中切模式会静默丢文件

- **现象**：加载过程中会 `processEvents`（让进度条动），期间用户若切模式，
  `on_spectrum_type_changed` 会清空 `data_cache` 并重新加载，而外层加载循环仍在
  往里塞——两部分互相踩，实测 40 个文件**静默丢 5 个**（丢的是随机的）。
- **修复**：`on_spectrum_type_changed` 加 `_loading` 守卫——加载中把下拉框拨回原值
  并在状态栏提示「请等加载完成后再切换模式」。

## 🧪 修复：回归测试直连真实注册表（工程缺陷）

- **现象**：`tests/run_regression.py` 的 `_session_settings_lend()` 是「摘下真实注册表
  里几个会话键 → 跑测试 → 回填」。但测试自己写入的键不在白名单里
  （`show_ex`、`subtract_enable`、`param/*` 等），根本不会被清掉；测试中途异常退出时
  回填也不执行。实测后果：注册表残留 `show_ex=true` 会让「减法扣本底」那项测试
  **多画两条 EX 竖线**（期望 2 条线、实际 4 条），报出一个**假失败**——
  排查时一度误判成代码 bug。
- **修复**：改为把各 GUI 模块里的 `QSettings` 符号替换成固定落到**临时 ini** 子类，
  测试全程不碰真实注册表。回填逻辑保留但恒为空操作（保持签名兼容）。
- 实测：跑完完整回归后注册表仍是干净的 5 键基线。
