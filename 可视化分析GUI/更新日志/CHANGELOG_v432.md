## 🐛 修复：归一化数据（峰值 = 1）无法拟合，报「拟合窗口 50 点，欠定」

**症状**：拿峰值 = 1 的作业/交换数据拟合寿命，稳定报

```
拟合点数不足：拟合窗口 50 点，自由分量 51 个（欠定问题，无法给出唯一解）
```

且把「速率点数」调小后虽然能跑，给出的寿命明显不合理（τ 顶到网格上界 100 ns）。
日志里无论 `n_rates` 设成 51 还是 201，窗口**始终是 50 点**。

**根因**：拟合窗口的噪声判据含一个**绝对**下限

```python
noise_level = max(decay_max / 500, 10, 1.5 * 本底)
```

其中的 `10` 是针对**原始光子计数**写的（v4.2x 为修「本底高的数字化谱图」而加，
真实计数数据峰值 10³~10⁵、本底几十，该下限几乎不生效）。而作业数据常被归一化成
峰值 = 1 的**相对强度**，于是：

| 量 | 归一化数据上的值 |
|---|---|
| `decay_max` | 1 |
| `noise_level` | `max(0.002, 10, 0.002)` = **10**（下限主导） |
| 所有通道 < 10？ | **是**（全部 2048 点） |
| `below_start` | 0（一开始就"进入噪声区"） |
| `fit_end` 原始值 | `0 + 衰减峰位 − 1` ＜ `fit_start`（IRF 峰位） |
| 结果 | 窗口退化成 `[IRF峰, 衰减峰)` 上升沿 → 被夹到 **50 点下限** → 欠定 |

**与数据质量无关**，是幅度刻度与判据不匹配。

**修复**：`preprocess()` 新增 `_rescale_if_normalized()`，在统计本底/噪声前先还原：

- 判据：衰减峰值 < `_NORMALIZED_PEAK_MAX`（**10**）视为归一化。
  真实计数数据峰值远高于此（工作区实测最低 3×10³），不会误伤。
- 还原：decay 与 IRF 乘**同一个**因子，峰值 → `_RESCALE_TARGET_PEAK`（**10⁴**），
  保持两者相对比例（IRF 基线扣除依赖该比例），再据此定噪声水平与拟合窗口。
- 透明：`info` 记录 `rescaled_from_normalized` / `rescale_factor` /
  `decay_peak_before_rescale`，GUI 信息页显示一行提示，**不是静默换算**。

**效果**（同一份归一化数据，`n_rates=201`）：

| | 拟合窗口 | 结果 |
|---|---|---|
| 修复前 | 50 点 | 报错（欠定） |
| 修复后 | 432 点 | τ = 2.92 ns（色氨酸文献值 ≈ 3 ns） |

**精度说明**：还原恢复的是"噪声判据的物理量级"，**不是与计数刻度逐位复现**——
绝对下限 `10` 在两种刻度下相对强度不同，窗口端点差几个通道。实测
`esipt-1/Decay2.csv` 真实计数刻度与"归一化后自动还原"两种输入的**主寿命差 0.07%**
（6.1053 vs 6.1007 ns）；而**不还原**时窗口退化成 50 点、τ 偏到 200 ns（偏差 3176%）。
结论：能拿到原始计数就用原始计数；只有归一化数据在手时，这层还原保证结果可用。
计数数据路径**完全不变**（实测 `rescale_factor` = 1，窗口/χ²R/τ 与 v4.31 逐位一致）。

## 🩺 改进：窗口被下限托底时给出可操作的诊断

修复前，窗口被托底只会提示"把速率点数降到 ≤ N"——但 50 点拟 49 个自由分量仍是
准欠定，等于拟合噪声，给出的寿命没有意义。现在 `info['window_floored']` 会标记
该情形，`fit()` 据此改报诊断：

```
本次拟合窗口是被 50 点下限托底的（噪声判据在衰减峰附近即触发），
依据：噪声水平 = …, 衰减峰值 = …, 本底 = …；
请依次检查：
  1) 衰减列是否为计数（峰值过低/被归一化会导致判据失效）；
  2) IRF 是否与衰减同窗、且有明显上升沿；
  3) 数据是否需要先去背景/去尖峰。
```

新增 `info` 字段：`window_floored` / `fit_end_raw` / `noise_level`，可程序化读取。
