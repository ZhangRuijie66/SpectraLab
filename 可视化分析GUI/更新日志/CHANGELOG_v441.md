## 🐛 一、修：说明.xlsx 明明在文件夹里，软件却说"未找到 / 读取失败"（用户反馈）

**症状**：`20261010` 批次文件夹里放着 `说明.xlsx`，但程序状态栏一直显示
「说明.xlsx 未找到或读取失败，图例使用文件名」，图例只有文件名、没有浓度，
「数据比较」的变量下拉框也是灰的、写着「未找到说明.xlsx」。

**原因**：这个批次的 `说明.xlsx` 把**「编号」列写成了文本码**：

| 编号 | RB浓度 | Ce6浓度 | L8i浓度 |
|------|--------|---------|---------|
| R1   | 50     |         | 1000    |
| S1   |        | 50      | 1000    |

而 `read_xlsx_info.load_xlsx_info` 对每一行都做 `int(raw_num)`——
`int('R1')` 抛 `ValueError`，被 `except` 吞掉 `continue`，**7 行全被丢掉**，
`numbers` 为空，函数直接 `return None`。界面上就等于"没有说明表"。

之前 6 个批次的编号列都是整数（`1/2/3…`），所以这个坑一直没暴露。

**修法**：

- 编号列不再强制整数：整数仍是 `int`，文本码按「去空白 + 统一大写」规范化成
  `str`（`'r1 '` → `'R1'`），空单元格 / `null` / `-` 仍旧算无效行；
- `match_number` 同时认整数与文本码：先看整体、再切片 token（`R1-2.csv` →
  `R1`），文本码**不做子串匹配**（`R1` 不会命中 `R10`）；整数编号的退化子串匹配
  原样保留，老批次行为不变；
- `XlsxInfo` 新增 `entry_for()`；`label_for` / `value_for` 改用它取值——
  此前它们写死 `self.info.get(int(number), {})`，编号是 `R1` 时同样抛
  `ValueError`（`gui_data._format_info_brief` 与 `plot_compare` 里还各有一份
  一模一样的 `int(num)`，一并改掉，否则值取不出来）；
- `build_enriched_label` 判断"基础标签就是编号"时也用同一套规范化，
  文本码标签（`R1`）现在能正确写成 `#R1 RB浓度=50, L8i浓度=1000`。

**验证**（真实数据 `20261010`，26 个 CSV + 说明.xlsx）：修复后读出 7 个样品
（R1/R2/R3/S1–S4）、3 个数值列；`R1.csv` / `R1-6.csv` / `S1-1.csv` / `S4-4.csv`
全部正确命中，且 `R1` 与 `S1` 不再串台（旧写法会把两者都退化成整数 1）。

## ✨ 二、新增：多列光谱 xlsx 能在**吸收模式**下加载（20261010.xlsx）

**需求**：`20261010.xlsx` 是仪器导出的 Excel 多光谱表——第一列 `波长(nm)`，
后面 7 列是样品（表头 `20261010R1 - RawData` … `20261010S1 - RawData`）。
（同文件夹那 26 个 CSV 是**发射**光谱：Ce6 在 669 nm 处约 2.6×10⁵ counts；
这个 xlsx 的纵轴是 0–4 的吸光度，属**吸收**光谱。）

**做法**：

- `read_xlsx_info` 新增 `parse_spectrum_xlsx()` / `clean_xlsx_column_label()`：
  一个工作簿按列拆成多条光谱，列名清成样品名
  （`20261010R1 - RawData` → `R1`），波长统一按**升序**排好；
- `plot_absorption.load_absorption_spectra` 接受 `.xlsx`，展开成多条吸收光谱
  （键仍是 `wl` / `absorption` / `label`，CSV 路径不受影响）；
- 吸收模式的文件夹加载把 `.xlsx` 一并收进来（排除 `说明.xlsx` 与 Excel 的
  `~$` 临时文件）；一个文件出多条时缓存键就是样品名，图例编号匹配新增
  `_match_sample_number`——候选名（真实文件名 / 缓存键）里**能对上编号的那个优先**
  （顺带修好了寿命模式多列 xlsx 的同类问题）；
- **不是**这种表就明确拒绝，判据是硬的：
  - 表头里**必须有一列**是波长列（列名含 波长 / wavelength / wl / nm），
    不猜第一列；
  - 只有波长列**右边**的列才当样品列（左边的"序号"之类一律忽略）；
  - 每列与波长轴对齐后 ≥10 个有效点。

  因此 `说明.xlsx`、`lifetime_fit_results_summary.xlsx`、"序号 + 数值列"的汇总表、
  `time (ns) + A0 + IRF` 的多列衰减表都不会被误收。全库 10 个真实 xlsx 复扫，
  **只有 `20261010.xlsx` 被认下（7 条）**。
- `clean_xlsx_column_label` 的仪器后缀正则要求短横线后有空白——`Sample-absorption`
  这种正常样品名不再被切成 `Sample`。

**验证**：吸收模式加载 `20261010` 文件夹 → 7 条吸收光谱 R1/R2/R3/S4/S3/S2/S1
（每条 1001 点、400–900 nm）；图例显示 `RB浓度=50, L8i浓度=1000` 等；
「数据比较」按 RB浓度出 3 个点（R1/R2/R3），S 系列按「为空」跳过。
同文件夹在**发射模式**下仍按老规矩只收 26 个 CSV（xlsx 不掺进来），
图例照常带浓度与 EX。

> 复核记录：本版本改动经过一轮独立只读复核（含 3 万组随机差分对照旧实现、
> 6 个真实批次的 `match_number`/`value_for`/`label_for` 全字段比对、全库 xlsx 复扫）。
> 复核提出的 4 处缺陷（波长列不在首位时左侧列被误当样品、兜底判据拦不住汇总表、
> 时间轴词边界漏洞、`_norm_code(float('inf'))` 抛 `OverflowError`）与
> 1 处误伤（列名后缀正则）已全部按上述判据修掉。

**验证**：吸收模式加载 `20261010` 文件夹 → 7 条吸收光谱 R1/R2/R3/S4/S3/S2/S1
（每条 1001 点、400–900 nm）；图例显示 `RB浓度=50, L8i浓度=1000` 等；
「数据比较」按 RB浓度出 3 个点（R1/R2/R3），S 系列按「为空」跳过。
