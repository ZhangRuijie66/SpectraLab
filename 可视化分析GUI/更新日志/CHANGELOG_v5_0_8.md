## 🔴 「⤓ CSV」点了毫无反应 —— 静默失败

### 现象

光谱积分结果表下方有两个按钮：**复制结果**、**⤓ CSV**。点「⤓ CSV」
**什么都不发生**：不弹目录选择框、不落文件、不报错、状态栏也不动。

这不是概率性故障，是**必然发生**——从 v4.26 加上这个按钮起就一直如此。

### 根因

`QPushButton.clicked` 会带一个 `bool` 实参。PyQt 在把信号接到 Python 槽时：

* 槽**只收 self**（`def _copy_integration_results(self)`）→ 自动截断多余参数；
* 槽**带可选参数**（`def _export_integration_csv(self, save_dir=None)`）→
  会把 `False` **塞进 save_dir**。

而函数体开头是这两句：

```python
if save_dir is None:          # ← 收到 False，判断失效，不弹目录框
    save_dir = QFileDialog.getExistingDirectory(...)
if not save_dir:              # ← False 是假值，静默 return None
    return None
```

于是整条链路在第二句就退出了，**没有任何一处告诉用户**。

`_export_compare_csv`（数据比较页的 CSV 按钮）是同一份签名，
**同一个 bug**，一起修。

### 修法

新增 `_resolve_save_dir()`：只有**非空字符串**才当作「预置目录」，
`False` / `True` / `None` 一律视为「没有预置目录」→ 退回弹目录框。
两个导出函数开头都先过一遍。

### 为什么回归测试一直没抓到

`tests/run_regression.py` 与 `test_batch3_smoke.py` 都这样测：

```python
out = w._export_integration_csv(save_dir=tmp)    # ← 直接调，绕过了信号
```

**等于替被测代码把参数填好了**。绕过信号就测不到「信号传了什么」。
本批新增的回归项改成 `w.integ_csv_btn.click()`，让 PyQt 自己去传那个 `bool`。

## 🟠 「框选后 Ctrl+C 复制选中行」是句空话

积分表的 tooltip 与帮助正文都写着「点表头可排序，**框选后 Ctrl+C 复制选中行**」。
实测：框选 7 行按 Ctrl+C，剪贴板里只有 **4 个字符**（当前单元格 `1000`）；
选中多行也只有一格。

原因很直接：**`QTableWidget` 没有内置复制**。以前没人发现，是因为
「复制结果」按钮能拿到整张表，大家用的都是那个按钮。

### 修法

积分表换成 `CopyableTableWidget`（`gui_plot.py`），补三件事：

| 按键 | 行为 |
|---|---|
| `Ctrl+C` / `Ctrl+Insert` | 复制**选中行**（制表符分隔，按表格**当前显示顺序**，即点了表头排序之后的顺序） |
| 无选中时按 `Ctrl+C` | 退化为整表（与「复制结果」按钮同口径），不静默失败 |
| `Ctrl+A` | 全选行（默认只选单元格，复制出来仍是一格） |

「复制结果」按钮也改成**遵循选中范围**：选中几行就只复制那几行，状态栏
会写「已复制选中的 N 行（全表 M 行）」。没选中时行为与以前完全一致。

## 🟠 700–800 nm 的谱配 450–550 nm 的积分区间 → 结果表永远是空的

### 现象

打开一份 700–800 nm 的发射谱：图上画得好好的，下方「光谱积分」却是一张
**空表**，标签写着「无数据重叠」。此时「复制结果」「⤓ CSV」两个按钮
都只弹"暂无结果"——**积分功能对这份数据整个不可用**，而界面上没有任何
一处告诉他"去把起止波长改一下"。

### 根因

程序里有**两套**波长范围：

| 范围 | 初值 | 加载数据时会不会按数据校正 |
|---|---|---|
| **显示范围** `wl_min/max` | 200–900 | ✅ 会（`_auto_set_range`，v4.x 的 E2 项） |
| **积分区间** `integ_min/max` | **450–550** | ❌ **从不校正** |

积分区间一直是出厂默认值并随会话记下来，于是任何不覆盖 450–550 的谱
都拿不到积分结果。

### 修法

新增 `_auto_set_integ_range()`，与显示范围**同一时机**调用（某文件夹首次加载、
或点「自动」按钮）。判据刻意保守——只在**明显不合理**时动手：

| 情况 | 动作 |
|---|---|
| 积分区间与数据**完全无重叠** | 改成数据实际范围 |
| 区间**超出**数据范围且跨度 > 数据跨度 × 1.5 | 收窄到数据范围 |
| 区间落在数据内（哪怕很窄，如 620–640） | **一律不动**——那是用户选的分析窗口 |
| 区间填反（结束 < 起始） | **不动**，保留「积分范围无效」提示，不替用户猜 |

校正后状态栏与日志都会写明「原区间 X–Y nm → Z–W nm，原因」。

## 回归测试（+3 项，共 92 项）

| 新增检查项 | 守的是什么 |
|---|---|
| 积分结果：导出 CSV 走「真实点击」路径也能落盘 | `clicked` 的 bool 顶掉 `save_dir` → 静默不导出；同时验证 `_export_integration_csv(False)` 不静默 |
| 积分结果：表格框选后 Ctrl+C 复制的是选中行 | 原生 `QTableWidget` 只复制一格（或空）；含「按钮遵循选中范围」与「无选中→整表」 |
| 积分区间：与数据不重叠时自动校正，结果表不再静默为空 | 三种情形：无重叠→校正、用户窄区间→保留、填反→保留 |

> 这三项的共同点：**都走真实控件路径**（`btn.click()` / `QTest.keySequence`），
> 不再直接调内部函数。上面那个 CSV bug 活了一年多，就是因为旧写法等于
> "替被测代码填好参数"。

## 兼容性

| 项目 | 是否变化 |
|---|---|
| 模块名 / 公开函数名 / 参数顺序 | 不变 |
| 导出 JSON 字段 / CSV 表头 | 不变（仍是「样品 / 起始波长 (nm) / 结束波长 (nm) / 积分值」） |
| 设置键（QSettings） | 不变 |
| 积分算法与数值口径 | 不变（仍是梯形积分、原始强度） |
| 积分**区间**的默认值 | 由「固定 450–550」变为「按数据校正一次」——**这是唯一的行为变化**，且只在原区间明显不可用时生效 |

若你依赖「每次打开都是 450–550」这个固定值，改完后第一次加载会被校正一次；
之后该文件夹不再重复校正，手填的值照旧保存与恢复。
