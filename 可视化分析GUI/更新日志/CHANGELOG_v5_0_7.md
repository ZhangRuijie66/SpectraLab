## 🆕 三个新分析模块接入 GUI

审计 B 的结论是「六种模式里只有寿命模式能出**数字**，其余五种只能出图」。
本批把三个补数字能力的模块接进界面。

### ① 谱带分解（吸收 / 发射）

`plot_bands.py`（1931 行）接入为参数栏一个分组：

| 控件 | 作用 |
|---|---|
| 峰形 | 高斯 / 洛伦兹 / 伪Voigt |
| 峰数 | 自动（BIC 定阶 + 可分辨性守卫）或 1–6 |
| 本底 | 常数 / 线性 / 不扣 |
| 用「显示范围」当拟合窗口 | 默认勾选（窗口越窄，「有几条带」越明确） |

**解决的真实问题**：`find_peaks` 只能拿局部极大——罗丹明的振动肩峰根本不是
局部极大、ESIPT 双发射要的是两带**面积比**、稀土多带彼此重叠。
实测罗丹明数据分解出 2 峰（521.0 宽带 + 548.5 主峰），R²=0.9990。

面积用**解析式**（高斯 √(2π)σh、洛伦兹 πγh），不做数值积分：
梯形积分会把宽洛伦兹尾按窗口截断而系统性偏小。

### ② 线性标定 + LOD（吸收 / 发射）

`plot_calibration.py`（2240 行）接入：横轴变量下拉框 + 一个按钮。

产出：斜率 / 截距 / R² / 回归标准误 / **LOD / LOQ** / 线性范围 / 失拟检验。
实测 05 数据 RB 标定：slope=136.68、**R²=0.9686**、LOD=10.20，
并**自动排除**了可比性预检判出的 `R1-3`（激发波长 650 vs 520）。

### ③ EEM 定量读出（3D 扫描）

`plot_eem_quant.py`（1598 行）接入：发射区间上下限 + 一个按钮。

产出：最佳激发波长 / 每个 EX 的发射峰位与**峰位漂移** / 发射带面积 / CSV。

**这个模块最特别的地方是它会说「不可信」**。实测示例数据 04：

| 判据 | 实测 | 阈值 |
|---|---|---|
| 饱和占比 | **11.35%**（8037 点） | 2% |
| 周期伪迹强度 | **77.8×**（周期 6.941 nm） | 20 |
| EM 通道平滑度 | **0.374** | 0.06 |
| 分块最佳 EX 一致性 | **86%**（600/539/581/514） | 25% |

→ 判为不可定量，信息页顶部直接写「⛔ 数据未通过可定量性诊断，
下列数字仅供参考，不要直接写进报告」。

## 🆕 导出产物溯源（`gui_provenance.py`）

审计实测：导出的 JSON 里拟合参数是齐全的，缺的只是「谁导的、什么时候、
从哪个文件、什么版本」。于是拿三周前的产物回来，无法判断是否还与本版
算法可比（算法改过，数字可能不可比）；PNG 更彻底，只有 matplotlib
自塞的 `Software` 标签。

新增 `gui_provenance.py`，接入 `_savefig_pub`（一处覆盖全部导出图）：

- **图角打一行小字水印**：版本 · 时间 · 源文件（≤3 个列全名，多了只列首名+数量）
- **产物旁写 `<name>_meta.json`**：完整 meta（含运行环境快照 numpy/scipy/
  matplotlib/Qt 版本、影响数值的参数快照）
- **可比性警告进产物**：v5.0.6 的预检提示只在状态栏停留几秒，写进产物才能
  「换个时间看也知道当时提示过什么」
- 寿命结果 JSON 也补了 `meta` 字段

水印刻意做得**很小很淡**（6.5pt、85% 透明度、放在角落）：它是给"日后回看"
用的，不该抢数据的视觉注意力。

## 🐛 修掉的三个 bug（都是我在做 GUI 集成时踩出来的）

### 1. 首帧模式专用选项全部隐藏（既有 bug，不只影响新功能）

各选项组建出来时都是 `setVisible(False)`，靠 `on_spectrum_type_changed`
信号来显示。但**初始 index 就是 0（吸收）**，`setCurrentIndex(0)` 不产生
变化信号 → 信号永不触发 → 吸收模式下发射/寿命/3D/谱带分解/标定**全部**
停在隐藏态。

既有的显隐测试只在"切换模式"路径上验过，**首帧状态一直是盲区**。

修法：抽出 `_sync_mode_groups_visibility()`（只动显隐，不清缓存不重载），
在 `__init__` 的 `setup_ui()` 之后主动调一次。

### 2. `qc_notes` 是 dict 却按 list 切片

标定结果信息页写的是 `notes[:5]`，而 `qc_notes` 实际是
`{样品名: 说明}` 的 dict → `unhashable type: 'slice'`。
改为 dict/list 双兼容。

### 3. `PlotWorker.progress` 是双参数信号

`progress = pyqtSignal(int, str)`，我只 emit 了一个参数。
这种错误 `py_compile` 抓不到（信号 emit 是运行时解析），
只能靠读代码发现。

## ⚠️ 一个必须记录的工程事故

集成过程中我的编辑工具把 **6 个文件的行尾从 LF 写成了 CRLF**。
本仓库 `core.autocrlf` 未配置、git 里存的是 LF，于是：

```
git diff --stat  （错误状态）
plot_compare.py    | 2090 ++---
gui_data.py        | 4432 +++++-----
gui_plot.py        | 8660 +++++++++++---------
→ 8 files changed, 15775 insertions(+), 14830 deletions(-)
```

**实际改动只有 963 行。** 归一化回 LF 后 diff 立刻恢复正常。

教训：改完文件要核 `git diff --stat` 的量级是否与预期相符；行尾被批量
翻转时，diff 会出现"整个文件都变了"的特征（增删行数接近文件总行数）。
建议给仓库加 `.gitattributes` 的 `* text=auto eol=lf` 兜住。
