## 一、空状态插画（替掉原来那个 56px 小图标）

没数据时画布上原来只有一个文件夹小图标，信息量太低。本版换成一张**插画**：
一张"光谱卡片"——圆角卡片外框 + L 形坐标轴 + 吸收边曲线 + 曲线上的取样点 +
两条网格虚线。构图刻意与四个模式图标同一套视觉语言（坐标轴 + 曲线），
但线更细、留白更多，放大显示也不显笨重。

**尺寸是特意这么定的**：插画按 **2 倍图**（400×240）交付，代码里给它标上
`devicePixelRatio = 2`，界面上就是 **200×120 逻辑像素**——用户的屏幕是
200% 缩放，只有这样才能原生清晰；直接塞 1 倍图会被系统放大到发虚。
三套主题各一张（浅 / 深 / 高对比纯黑）。

**降级链**（打包漏资源也不会白屏）：插画 → 单色大图标（`folder_open` 56px）→ emoji。

## 二、首次使用引导：三步上手

空状态最容易犯的错是"只说一句『请选择数据文件夹』"——第一次用的人仍然不知道
后面两步要干什么。现在在主按钮下方并排摆三张小卡片，把整条主路径写清楚：

| 步 | 标题 | 说明 |
|---|---|---|
| **1** | 选择数据文件夹 | 点下面的按钮，或把文件夹拖进来 |
| **2** | 选类型 / 调参数 | 左栏顶部切类型，右侧「参数」栏调整 |
| **3** | 预览并导出 | 按 F5 出图，再从「导出」菜单选格式 |

- **第 3 步随模式变**：荧光寿命模式下主操作不是预览而是拟合，文案自动改成
  「主按钮是『开始拟合』，单文件约 1–2 分钟」——不会让用户在寿命模式里
  到处找那个并不存在的"预览"。
- **可收起、可再展开**：下方「不再显示这三步」一键收起，偏好记进会话
  （`ui/onboarding_hidden`），下次启动仍是收起状态；收起后按钮变成
  「显示上手指引」，随时可以再展开。
- 有数据时整页自动让位给画布（v4.27 起就是 画布/空状态 两页堆叠）。

## 四、顺带补回：mac 打包脚本（事故遗留项）

2026-09-10 那次目录事故里丢掉了一个文件：`mac打包文件夹\build_mac.command`（macOS 打包脚本）。
它之所以找不回来，是因为**它同时掉在三张网之外**：

- `mac打包文件夹\` 被 `.gitignore` 排除 → 不在 git 里；
- 它不在 `同步到mac文件夹.ps1` 的 SYNC-MANIFEST 里 → 同步不会覆盖/校验它；
- 只在 mac 副本里存在一份 → 事故后没有第二份。

本版把它**重写**并调整了存放方式：

| 项 | 做法 |
|---|---|
| 权威副本 | 放到 **GUI 根目录** `build_mac.command`（受 git 跟踪） |
| 同步 | SYNC-MANIFEST 新增 `app\|build_mac.command`（28 → **29 条**），自动同步到 mac 副本并校验 SHA |
| 换行符 | 新增 `.gitattributes`：`*.command` / `*.sh` 强制 **LF**——本仓库 `core.autocrlf=true`，CRLF 的 `#!/bin/bash` 在 macOS 上会直接报 `bad interpreter` |
| 可执行位 | git 索引里记为 `100755`，macOS 上检出即可 `./build_mac.command` |

脚本内容与 Windows 的 `打包便携版.ps1` 同一套参数，只有两处平台差异写明了：
`--add-data` 用 `:` 分隔、图标要用 `.icns`（脚本内用 Pillow + `iconutil` 从 `.ico` 转，
失败则不带图标继续打包）。首次运行自动建虚拟环境装依赖，之后重跑只做打包。

至此 `检查版本一致性.py` 的 **11 项全部通过、0 警告**（此前一直挂着"mac 打包脚本缺失"这条告警）。

## 七、备注

- 插画是**位图**、跟主题走；改画法只需改 `生成图标.py` 里的 `illus_empty()`
  再跑一次 `python 生成图标.py`（脚本会打印自检：不透明占比、包围盒）。
- 三步指引的文案故意写得短——默认三栏布局下画布只有约 460px 宽，
  三张卡片各占约 140px，写长了每张都要折成三行。
  把左右栏收起（`Ctrl+3` 只看图）后再回空状态，卡片会显得宽松很多。
