## 🔴 修复：静默失败类（用户看不出错，但产物是错的）

### 深色主题下「导出用白底」完全失效

- **现象**：深色主题用户勾着「导出用白底」（默认勾选），导出的其实是**黑底灰字**
  （对比度约 1.5:1），而弹窗说"已保存"。投稿时直接废掉。
- **根因**：`_savefig_pub` 只改 `fig.patch`，但 `savefig.facecolor` 这个 rcParam
  优先级更高，且被 `_apply_mpl_theme` 设成了主题深色 `#0b1220`。
  浅色主题恰好也是白底，所以这个 bug **只在深色下暴露**。
- **修复**：`fig.savefig(..., facecolor=fig.get_facecolor())`。
- 实测：深色下角落像素 `(11,18,32)` → `(255,255,255)`。

### 换文件夹 / 切模式后不清派生结果 → 导出的是上一批数据

- **现象**：切到 B 文件夹后导出，产物里出现 A 文件夹的样品名，弹窗照样说"成功"。
- **根因**：`data_cache` 被清空了，但 `_last_lifetime_result` / `_last_integration_results`
  / `_last_compare_result` / `_last_scan3d_result` / `_overlay_results` **没有任何清空点**。
- **修复**：新增 `_invalidate_results()`，在 `load_data_from_folder` 与
  `on_spectrum_type_changed` 两处集中作废，并同步清空积分结果表、隐藏拟合摘要卡片。

### 画布只有提示文字时照样"成功"导出空白图

- **现象**：①寿命模式还没点「开始拟合」就导出 → 得到两张只写着"请点击开始拟合"的图；
  ②把样品全部取消勾选后「导出当前图」→ 导出一张写着"请勾选至少一个文件"的图。
  两种情况弹窗都说"已导出"。
- **修复**：新增 `_canvas_is_placeholder()` 判定画布上是否真无数据；
  `_export_lifetime_plots` 在无拟合结果时明确拒绝并提示先拟合。

### 3D 扫描三种绘图类型导出互相同名覆盖

- **现象**：3D 曲面 / 等高线 / Waterfall 导出到同一目录，连导 3 次只剩 1 个 PNG
  （留下最后一张），用户以为三种图都导出了。
- **根因**：`_current_plot_title()` 对 scan3d 不含绘图类型。
- **修复**：标题带上类型，导出名形如 `3D扫描 - 样品 - 等高线 (俯视图).png`；
  同时把 `plot_type` 写进 `_stats.json`，便于溯源。
- 实测：同一目录三种类型 → 3 个互不重复的 PNG。

### 寿命结果 JSON 中文被转义成 `\uXXXX`

- **修复**：`json.dump` 补 `ensure_ascii=False`（同仓 3D 的 stats.json 本来就是写对的）。

## 🟠 修复：无提示崩溃与失效

### `launch_hidden.py` 无异常钩子：槽函数抛异常 → 进程直接 abort

- **现象**：桌面快捷方式（`.lnk`）与 `run_gui.bat` 实际走的都是 `launch_hidden.py`，
  而该入口**完全没有** `gui_log` 引用。PyQt5 对从槽函数逃出的异常直接 abort：
  无 traceback、无日志、窗口瞬间消失。
- **实测**：子进程退出码 `3221226505` = `0xC0000409`；装了钩子的同一场景 exit=0。
- **修复**：把 `setup_logging()` + `install_excepthook()` 移进 `setup_ui()` 开头，
  一次覆盖**全部入口**（函数内部幂等，重复调用无副作用）。

### 主按钮体系回潮：同屏 5 个实心主色按钮

- **现象**：有数据时同屏出现 5 个实心蓝按钮（选择数据文件夹 / 重新加载 / 数据比较 /
  实时预览 / 复制结果），与设计方案 §5.1「每屏 1 个主操作」冲突，用户不知道先点哪个。
- **修复**：只保留参数栏「操作」区的 `preview_btn`（寿命模式自动变「开始拟合」）为
  primary；「选择数据文件夹」随空状态动态切换（无数据 = 主操作，有数据 = 次级）；
  其余三处降为 secondary。
- 实测：有数据时 5 个 → **1 个**；空状态 1 个；寿命模式 1 个（「开始拟合」）。

## 🟡 修复：绘图正确性

### 归一化遇负基线爆炸（合并图整张废掉）

- **现象**：本底没扣干净、带负基线的谱（如 EtOH 空白 min=−66.1 / max=6.04）
  归一化后最低到 **−10.95**，整张合并图纵轴被拉到 (−12.15, 2.2)，
  所有真实样品（0~1）被压成贴着零线的细线。
- **根因**：`y / np.nanmax(y)` —— 负基线除以正值，负向被放大 11.9 倍。
- **修复**：新增 `_normalize_intensity()`，改为**扣基线后按峰高归一**：
  `(y - min) / (max - min)`。GUI 两处（预览 / 导出）与根模块 `plot_emission.py`
  共用同一口径，实测两边输出完全一致。
- **对历史图的影响**：正常谱（基线≈0）差异 < 0.3%（峰值 1001.8 / 基线 2.0 时
  逐点最大差 0.002）。负基线谱从 `[-10.94, 1.00]` 变为 `[0, 1]`。

### `_apply_xlim` 把 EX 竖线当成数据

- **现象**：勾「标注 EX」+ 填「显示范围」同时启用时，曲线被压到纵轴中部——
  实测曲线占纵轴比例从 83% 掉到 **41.7%**，纵轴跨度被撑大 2.4 倍。
- **根因**：`axvline` 的 `ydata` 恒为 `[0, 1]`（轴坐标分母），它不是数据，
  但旧代码只按 ndim/size 过滤，竖线顺利通过并把 Y 下限拉到 0。
- **修复**：跳过 `xdata` 恒为常数（竖线）或 `ydata` 恒为常数（横线/零基准线）的线条。
- 实测：曲线占纵轴 41.7% → **83.4%**；零基准线被正确跳过，不影响正常光谱。

## 🎨 修复：界面

### 停靠面板 QSS 块解析失败，连带其后 6 条规则全部失效

- **现象**：三栏标题栏变成亮灰 `#dadada`（深色下最刺眼），面板无卡片底色与圆角，
  关闭/浮动按钮无图标，栏开关条样式丢失——**三套主题都中招**。
- **根因**：`url()` 里图标文件名形如 `close_light@24.png`，**未加引号**。
  Qt 的 QSS 解析器在 `@` 处**整块放弃**，并让该块之后的所有规则一起失效。
  Qt 不给行号，只打印 `Could not parse stylesheet`。
- **修复**：`url("{path}")` 加引号（2 行）；并在 `apply_style` 收尾加一道自检，
  主动扫出「未加引号且含 `@` / `%` / 空格」的 `url()` 并记日志，防止回潮。
- 实测：顶层 121 个块中解析失败数 `2 → 0`；QSS 未加引号 `url()` 归零。

### matplotlib 工具条图标被 DPI 放大到 48px，吃掉 15.6% 画布高度

- **现象**：1440×852 下画布只剩 351px 高，工具条比图还抢眼。
- **根因**：Fusion 在 192 DPI 下把 `PM_ToolBarIconSize` 算成 48，mpl 工具条直接继承；
  栏开关条显式设了 16px，唯独这里漏了。
- **修复**：`tb.setIconSize(QSize(20, 20))`。
- 实测：工具条占比 15.6% → **8.0%**。
