## 3. 关于 torch / rich（**重要**）

- 本机**全局环境里确实存在** `torch==2.13.0+cu126`、`torchvision==0.28.0+cu126`、
  `rich==15.0.0`——但它们属于**其它项目**，**不是本程序的依赖**。
- `打包便携版.ps1` 用 `--exclude-module` 明确排除了它们：
  `torch`、`torchvision`、`tensorflow`、`rich`、`sympy`、`IPython`、`jedi`、
  `lxml`、`zmq`、`notebook`、`ipykernel`、`nbconvert`、`nbformat`、`jupyter_core`、
  `prompt_toolkit`、`matplotlib_inline`、`ipython_genutils`、`tkinter` 等。
- **因此：新写的模块一律禁止 `import torch` / `import rich`。**
  一旦引入，PyInstaller 会把整个 torch 拖进依赖图，轻则 exe 体积从 ~101.6 MiB 暴涨到 2GB+，
  重则直接打包失败。参考算法如果来自 torch 实现，必须先"去 torch 化"
  （autograd 优化改 `scipy.optimize`，GPU multistart 改多起点循环）。
- 允许的直接依赖只有第 2 节那 8 个 + Python 标准库。

## 4. 依赖文件

| 文件 | 内容 | 用途 |
|---|---|---|
| `requirements.txt` | 人工整理的 8 个直接依赖 + 用途注释 + 版本 | 换机器时快速装齐直接依赖 |
| `requirements-lock.txt` | **项目闭包**：26 个包（8 个直接依赖 + 其全部间接依赖），钉死版本 | 复现同一套环境 |

生成方式（**只读，不安装/升级任何包**，2026-09-09）：

```powershell
cd "D:\北大\QLS Lab\SPC\1O2+luminol\谱图\光谱\画图\可视化分析GUI"
# 1) 让 pip 算出"从零装一遍需要哪些包"（--dry-run 只解析不安装）
python -m pip install --dry-run --ignore-installed --report $env:TEMP\pipreport.json -r requirements.txt
# 2) 交叉验证：importlib.metadata 递归遍历 requires（环境标记按 win32/py3.11 求值）
# 3) 版本号取本机已装版本（python -m pip freeze 对应项），即打包脚本验证过的组合
```

> 闭包**故意排除** torch / torchvision / rich / jupyter / ipykernel / nbconvert / sympy /
> lxml / psutil / requests / python-docx 等本机全局环境里存在、但属于其它项目的包
> （pip 解析结果与 importlib.metadata 遍历结果一致：26 个包，无上述大包）。
> 旧版 lock 文件是 `pip freeze` 的 87 包全量快照，会把 torch 一起带进来，已废弃。

## 5. 打包命令

在 `可视化分析GUI` 目录下执行：

```powershell
cd "D:\北大\QLS Lab\SPC\1O2+luminol\谱图\光谱\画图\可视化分析GUI"
powershell -ExecutionPolicy Bypass -File 打包便携版.ps1
```

- 脚本内部实际调用：`py -3.11 -m PyInstaller --noconfirm --clean --onefile --windowed
  --name SpectralAnalysisTool --paths <上级画图目录> --icon app_icon.ico
  --splash splash.png --hidden-import plot_* ... entry_gui.py`
- 耗时约 2–3 分钟。
- 产物：`便携版\光谱可视化分析工具.exe`（单文件，**约 101.6 MiB**；
  实测 106,585,262 字节 = 101.65 MiB，v4.20 构建）。
- 中间产物：`_packaging\build\`、`_packaging\dist\`（每次打包前会被清空重建；
  其中 101 MB 的 `SpectralAnalysisTool.pkg` 已移入 `_quarantine\`）。

**打包前请先跑版本一致性检查**：

```powershell
python 检查版本一致性.py
```

它会检查（v4.21 起）：

1. `gui_config.APP_VERSION` / `RELEASE_DATE` 能否读出；
2. 当前版本的 `更新日志\CHANGELOG_vXXX.md` 是否存在、有没有更高版本（版本回退）；
3. `splash.png` **内嵌的版本号**（PNG tEXt 键 `QLSVersion`）是否等于 `APP_VERSION`
   —— 不再比文件 mtime；
4. `便携版\光谱可视化分析工具.exe` 是否比**打包输入集合**
   （GUI 的 `*.py` + 绘图模块 + `splash.png` + `app_icon.ico`）新，**落后即 FAIL**；
5. 绘图模块清单由 `glob('plot_*.py')` **动态推导**（不硬编码）；
6. `打包便携版.ps1` 是否给全部绘图模块写了 `--hidden-import`（缺失 **FAIL**）；
7. `mac打包文件夹\build_mac.command` 的 `--hidden-import` 覆盖情况（缺失 **WARN**）；
8. mac 副本**逐文件 SHA256** 比对（清单唯一真源 = `同步到mac文件夹.ps1` 的
   `SYNC-MANIFEST` 区块；不一致 / 缺失 **FAIL**）；
9. 源码里是否残留硬编码版本号。

**改了版本号后必须重跑 `python 生成splash图.py`**（它会同时刷新 PNG 里的
`QLSVersion` 元数据），否则第 3 项会 FAIL。

## 6. 从零重建环境

适用于换机器、重装系统、或环境被搞乱的情况。

### 步骤 1：安装 Python 3.11

到 python.org 安装 **Python 3.11.x（64 位）**，安装时勾选
`Add Python to PATH` 和 `py launcher`。装完确认：

```powershell
python --version      # 应输出 Python 3.11.x
py -3.11 --version    # 打包脚本依赖这个
```

### 步骤 2：（可选但推荐）建虚拟环境

```powershell
cd "D:\北大\QLS Lab\SPC\1O2+luminol\谱图\光谱\画图\可视化分析GUI"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

> 注意：如果用了虚拟环境，打包脚本里的 `py -3.11` **不会**用这个 venv，
> 而是用全局 3.11。要么把依赖也装进全局 3.11，要么临时把打包脚本里的
> `py -3.11` 改成 venv 里的 `python`（改脚本前先确认，别直接提交）。

### 步骤 3：安装依赖

**方案 A（推荐，版本可控）**——只装直接依赖：

```powershell
python -m pip install -r requirements.txt
```

**方案 B（严格复现）**——按锁文件装全套闭包（26 个包）：

```powershell
python -m pip install -r requirements-lock.txt
```

> 方案 B 现在**不会**连带安装 torch 等大包 —— 锁文件已是本程序的项目闭包
> （见第 4 节）。若只想装直接依赖，用方案 A 即可。

### 步骤 4：验证

```powershell
# 1) 依赖是否齐
python -c "import PyQt5, matplotlib, numpy, scipy, pandas, openpyxl; print('DEPS OK')"

# 2) 版本一致性（只读检查）
python 检查版本一致性.py

# 3) 冒烟启动（会弹窗口，关掉即可）
python start_gui.py
```

三条都通过即环境就绪。

### 步骤 5：打包

```powershell
powershell -ExecutionPolicy Bypass -File 打包便携版.ps1
```

产物在 `便携版\光谱可视化分析工具.exe`。首次启动需要解压到临时目录并建字体缓存，
**实测等 25–40 秒属正常**，之后启动会快一些。

## 7. 常见环境问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 打包脚本报 `py -3.11 不是内部或外部命令` | 没装 py launcher 或没有 3.11 | 重装 Python 3.11 并勾选 py launcher |
| 运行时 `ModuleNotFoundError: plot_xxx` | 打包脚本漏写 `--hidden-import` | 在 `打包便携版.ps1` 里补一行，重打包 |
| 运行时 `ModuleNotFoundError: openpyxl` | 读 xlsx 缺引擎 | `pip install openpyxl`，并确认打包脚本有 `--hidden-import openpyxl` |
| 打包体积突然变成 GB 级 | 某个模块 `import torch` 了 | 去掉该 import，改用 scipy/numpy 实现（正常体积约 101.6 MiB） |
| 中文显示成方框 | 系统缺微软雅黑 / 字体缓存没建 | 确认 Windows 字体正常；首次启动多等一会 |
| 启动图版本号是旧的 | 改了 `APP_VERSION` 没重跑 `生成splash图.py` | `python 生成splash图.py` 后重新打包（检查脚本会读 PNG 元数据核对） |

清理要点：

- **只移动不删除**：历史产物进 `_quarantine\`，历史脚本进 `tests\_archive\`，

- 唯一被删除的是 `__pycache__\`（Python 会自动重建）。
- `_packaging\build_portable.py` 是**危险脚本**（会打出残缺 exe），
  已移入隔离区，原位置只留一个打印警告并 `exit 1` 的同名空壳。
- `.gitignore` 保证首次提交约 **3.15 MiB / 163 个文件**（上限 20 MB）；
  `git init` 与首次 `git add` 留给协调者执行。
